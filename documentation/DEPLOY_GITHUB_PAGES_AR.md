# نشر الموقع على GitHub Pages — الخطوات الكاملة

> هذا الملف يجيب على سؤال واحد: **كيف أُخرج الموقع من Google AI Studio إلى
> GitHub، وأجعله يعمل على رابط عام؟**
> كل ما هو مكتوب هنا مُنفَّذ فعلاً في المستودع، ويمكن التحقق منه بالأوامر المذكورة.

---

## 1. الصورة الكبيرة (اقرأ هذا أولاً)

المشروع الذي أخرجه Google AI Studio هو **تطبيق Vite + React**، أي أنه في النهاية:

```
src/ + public/  ──[npm run build]──►  docs/  ──[رفع]──►  GitHub Pages
```

`docs/` مجلد **مُولَّد**، لا يُحرَّر يدوياً. وأي نشر يعتمد على نسخة قديمة منه
سينتج موقعاً مكسوراً. لذلك أضفنا سير عمل يبني من `src/` في كل مرة:

| الملف | الوظيفة |
| --- | --- |
| `.github/workflows/deploy.yml` | يبني الموقع ثم ينشره على Pages عند كل دفع إلى `main` |
| `package-lock.json` | يجعل `npm ci` في سير العمل ممكناً (كان غائباً فتفشل كل عمليات CI) |
| `SITE_BASE` (متغيّر بيئة) | مسار النشر؛ افتراضيه `/-Project-/`، وسير العمل يضبطه على `/اسم-المستودع/` |
| `npm run site:check` | يفحص مجلد `docs/` قبل النشر: أصول ناقصة، قاعدة خطأ، EDB، EPUB |

**الرابط بعد النشر:** `https://ndt-insco.github.io/INSCONDT/`

---

## 2. خطوة لمرة واحدة: تفعيل Pages

لا يمكن تفعيل Pages من سطر الأوامر بحساب الروبوت (يرجع `403`)، لذلك تُعمل يدوياً
مرة واحدة من المتصفح.

> **«خانة Settings مش موجودة»** — تبويب Settings لا يظهر إلا للحساب المالك
> للمستودع (أو لمن لديه صلاحية Admin) وهو مسجّل الدخول. المستودع ملكه حساب
> **NDT-INSCO**، فلو إنت داخل بحساب آخر سترى الكود وActions فقط. على الموبايل
> يكون Settings داخل قائمة **•••** أعلى صفحة المستودع. وإن كنت لا تملك بيانات
> الحساب، استخدم البديل في القسم 9.

1. افتح `https://github.com/NDT-INSCO/INSCONDT/settings/pages`
2. في **Build and deployment → Source** اختر **GitHub Actions** (وليس
   *Deploy from a branch*).
3. لا تضبط Branch ولا Folder — سير العمل هو الذي يرفع النسخة النهائية.

انتهى. لن تحتاج لتكرار هذه الخطوة.

## 3. النشر

### أ. النشر التلقائي (المعتاد)

أي دفع إلى `main` (أي دمج Pull Request) يشغّل `deploy` وحده:

```
Actions → deploy → build → deploy → ✅
```

### ب. النشر اليدوي (عند الحاجة)

`Actions → deploy → Run workflow → Branch: main → Run workflow`

> **مهم:** لا تنتظر أن يظهر الموقع من فرع `arena/...`. Pages ينشر من `main`
> فقط، فالتغييرات تظهر بعد الدمج.

### ج. ماذا يفعل السير العمل بالتفصيل

1. `npm ci` بلا مفاتيح ولا أسرار.
2. `npm run build` مع `SITE_BASE=/INSCONDT/`، فيصبح كل أصل داخل
   `docs/index.html` على الشكل `/INSCONDT/assets/...`.
3. `npm run site:check` — يفشل السير العمل إن كان أي أصل مذكوراً وغير موجود.
4. رفع `docs/` كأثر (artifact) ونشره على Pages.

## 4. لماذا `/-Project-/` قديماً و`/INSCONDT/` الآن؟

GitHub Pages يعطي كل مستودع مساره الخاص:

```
https://ndt-insco.github.io/<اسم-المستودع>/
```

- المستودع القديم `NDT-INSCO/-Project-` ما زال ينشر نسخته من `docs/` في فرعه
  `main` على `https://ndt-insco.github.io/-Project-/`. **لن يتغيّر تلقائياً**
  عند نشر المستودع الجديد، لأن Pages خاص بكل مستودع على حدة.
- المستودع الجديد `NDT-INSCO/INSCONDT` ينشر على
  `https://ndt-insco.github.io/INSCONDT/`.

إن أردت إبقاء العنوان القديم، فأمامك ثلاثة خيارات:

| الخيار | الطريقة |
| --- | --- |
| تحديث المستودع القديم | انسخ `src/` و`package.json` و`.github/workflows/deploy.yml` إليه، واترك `SITE_BASE` بقيمته `/-Project-/` |
| إعادة توجيه | ضع في صفحة `index.html` القديمة تحويلاً إلى العنوان الجديد |
| نطاق خاص | `Settings → Pages → Custom domain`، ثم اضبط متغيّر المستودع `SITE_BASE` على `/` |

**لتغيير المسار:** `Settings → Secrets and variables → Actions → Variables →
New repository variable` باسم `SITE_BASE` وقيمة مثل `/` (نطاق خاص) أو
`/-Project-/`. سير العمل يستخدمها إن وُجدت، وإلا يستخدم `/اسم-المستودع/`.

## 5. المستشار الذكي (Gemini) على Pages

GitHub Pages يقدّم **ملفات ثابتة فقط**؛ لا يوجد خادم، ولا `POST /api/ai/chat`.
لذلك بعد النشر سيقول المستشار بصراحة إن البوابة غير مهيّأة — وهذا سلوك مقصود،
لا خطأ في النشر. راجع `documentation/AI_STUDIO_AR.md`.

لتشغيله فعلاً:

1. شغّل `server.ts` على خادم حقيقي (Cloud Run / VPS / أي مكان) واضبط عنده
   متغيّر البيئة `GEMINI_API_KEY` — **المفتاح لا يوضع في المستودع أبداً**.
2. أضف متغيّر مستودع باسم `VITE_AI_BASE_URL` وقيمته رابط الخادم، مثل
   `https://insco-tutor-xxxx.a.run.app`.
3. أعد تشغيل `deploy` (المتغيّر يُقرأ وقت البناء، فلا يكفي حفظه وحده).

بدون هذه الخطوات يبقى الموقع سليماً، وتعمل كل الأكاديمية والمكتبة والاختبارات
محلياً في المتصفح.

## 6. الأصول الثابتة (الصور والبروشور)

`public/` هو المجلد الوحيد الذي يُنسخ كما هو إلى `docs/`. أي رابط لملف فيه يجب أن
يمر عبر `assetUrl()` من `src/utils/assetUrl.ts`، لأن المسار المطلق مثل
`/images/x.jpg` يشير إلى جذر النطاق لا إلى مسار المستودع.

- صور الشركة: `public/images/*.jpg` → `assetUrl('images/...')`.
- البروشور: `public/assets/aistudio/...pdf` → `assetUrl('assets/aistudio/...')`.

**لا تكتب `/src/...` في أي رابط.** هذا مسار خادم التطوير فقط، ولا وجود له في
النسخة المنشورة؛ وجوده يعني صوراً فارغة على الموقع. `npm run site:check` يفشل
الآن إذا وجد أي `/src/` في `src/` أو `index.html`، ويتأكد أن كل ملف في `public/`
موجود فعلاً في `docs/` بنفس الحجم.

## 7. حل المشكلات

| ما تراه | السبب | الحل |
| --- | --- | --- |
| صفحة 404 على `…/INSCONDT/` | Pages غير مفعّل، أو لم يُشغَّل `deploy` بعد | نفّذ القسم 2 ثم أعد تشغيل سير العمل |
| صفحة بيضاء وشبكة الفحص مليئة بـ `404` على `/assets/...` | القاعدة (`base`) لا تطابق مسار النشر | تأكد أن `SITE_BASE` = `/اسم-المستودع/` في السير العمل |
| الأصول تعمل لكن الخطوط/الصور لا | نشر نسخة قديمة من `docs/` | `deploy` يبني من المصدر؛ لا تعدّل `docs/` يدوياً |
| الموقع يظهر ناقصاً بعد دمج | ذاكرة المتصفح | تحديث قسري `Ctrl/Cmd + Shift + R` |
| سير `verify` أحمر عند `npm ci` | كان `package-lock.json` غائباً | أُضيف في هذا الفرع؛ لا تحذفه |
| تبويب Settings غير ظاهر | الحساب ليس مالك المستودع ولا Admin | ادخل بحساب NDT-INSCO، أو استخدم القسم 9 |
| الصور فارغة والبروشور لا يفتح | رابط مطلق أو `/src/...` | استخدم `assetUrl()` كما في القسم 6 ثم `site:check` |
| الأكاديمية تعمل والذكاء الاصطناعي لا | لا خادم على Pages | القسم 5 |

## 8. التحقق قبل الدفع (محلياً)

```bash
npm install                      # Node 22 أو أحدث
npm run lint                     # فحص الأنواع
npm test                         # الاختبارات
npm run build                    # بناء إلى docs/
npm run site:check               # فحص ما سيُنشر

# محاكاة ما يفعله سير العمل تماماً:
SITE_BASE=/INSCONDT/ npm run build && SITE_BASE=/INSCONDT/ npm run site:check
```

## 9. بديل لا يحتاج Settings ولا صلاحية على GitHub

لو لم يكن الحساب الذي تستخدمه مالكاً للمستودع، فلن تقدر على تفعيل Pages. استخدم
استضافة ثابتة تقرأ من المستودع مباشرة:

**Netlify:** `Add new site → Import an existing project → GitHub → INSCONDT`

| الإعداد | القيمة |
| --- | --- |
| Build command | `npm run build` |
| Publish directory | `docs` |
| Environment variable | `SITE_BASE` = `/` |

**Cloudflare Pages:** نفس القيم (`SITE_BASE` = `/`).

الشرط الوحيد هو `SITE_BASE=/`، لأن غير ذلك يجعل كل الأصول تحت `/INSCONDT/` وهو
مسار يخص GitHub Pages.

---

## 10. أسرار لا تُرفع

- `GEMINI_API_KEY` — للخادم فقط، ويُقرأ من `.env` غير المتعقَّب.
- `.env*` مستثنى في `.gitignore` ما عدا `.env.example`.
- سير العمل لا يطبع أي سر ولا يمرّره إلى أمر البناء.
