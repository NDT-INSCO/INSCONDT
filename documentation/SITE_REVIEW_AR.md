## 3. عيوب وجدتها وأصلحتها في هذه المراجعة

### 3.1 حرجة — حجم التحميل الأول

الموقع كان يحمّل **2.9 MB JavaScript** (802 KB مضغوطة) قبل أن يرى المستخدم
أي شيء. السبب: `three.js` و Firebase داخل الحزمة الرئيسية رغم أن أحدهما
للتجربة ثلاثية الأبعاد فقط والآخر لخدمة غير مُهيّأة أصلاً.

| المرحلة | الحزمة الرئيسية | gzip |
| --- | --- | --- |
| قبل | 2,855 KB | 802 KB |
| بعد فصل three.js (تحميل عند فتح المعمل) | 2,356 KB | 688 KB |
| بعد فصل Firebase (تحميل عند مزامنة فعلية) | **1,843 KB** | **533 KB** |

الوفر: **~1 MB خام و 269 KB مضغوطة (-34%)**، وقُسم إلى:
`UtThreeScene` 569 KB · Firebase 513 KB — تُحمّل عند الحاجة فقط.

### 3.2 حرجة — خطأ في وحدة التحكم عند كل زيارة

`src/firebase/config.ts` كان ينفّذ `getAuth()` بلا `apiKey`، فيطبع
`auth/invalid-api-key` في وحدة التحكم عند **كل** تحميل. أُصلح:
- التهيئة تُنفَّذ فقط عند وجود `VITE_FIREBASE_API_KEY`.
- Firebase يُستورد ديناميكياً عند محاولة مزامنة فقط.
- رسالة المزامنة أصبحت: «Cloud sync is not configured; progress stays local».

### 3.3 عالية — اتجاه المستند لا يتغيّر مع اللغة

`<html lang="ar" dir="rtl">` ثابت. عند التبديل للإنجليزية يبقى اتجاه المستند
RTL، فتفسد قارئات الشاشة والترجمة الآلية. أُصلح: تحديث `lang`/`dir` عند كل
تغيير، مع **تذكّر اللغة** في `insco_language_v1` (كانت تعود للعربية عند التحديث).

### 3.4 عالية — لا يمكن مشاركة رابط لتبويب

كل شيء داخل حالة React بلا URL. أُضيف راوتنج خفيف بالـ hash:
`#courses`, `#paths`, `#practical`, `#edb`… مع `replaceState` (لا يتضخم تاريخ
التصفح)، وتراجع آمن عند hash غير معروف، و`initialSubTab` يتقدّم على الـ URL.

### 3.5 متوسطة — إفادة التعلم الذاتي قد تعرض `NaN`

لو عدّل المستخدم `insco_academy_completed_topics_v1` يدوياً بقيم غير مصفوفات،
كان المجموع يصبح `NaN`. أُضيف تحقق `Array.isArray`.

### 3.6 متوسطة — لا تحقق على النسخة المنشورة

`edb:check` كان يفحص `public/edb` فقط. لو نسي أحد بناء `docs/` لبقي الفحص
أخضر بينما الموقع ينشر مكتبة قديمة. أُضيف:
- `edb:verify:published` — بصمات `docs/edb` مقابل فهرسها.
- `site:check` — مسارات `docs/index.html`، `.nojekyll`، وجود كل ملف EDB،
  وميزانية حجم الحزمة.

كلاهما داخل `npm run verify` الآن.

### 3.7 منخفضة — تنظيفات

- حارس `createPracticalAssessment` لعدد الدرجات كان ملتوياً؛ صار شرطاً واحداً واضحاً.
- أزيلت حالة `'-'` المكررة في شرائح التبويبات.

## 4. النشر — الخطوات الدقيقة

العمل جاهز على `arena/8c16ed4e-project`. للنشر:

1. دمج الفرع في `main` (PR جاهز).
2. GitHub Pages يعيد البناء تلقائياً من `main`/`docs` خلال ~1–2 دقيقة.
3. تحقّق بعد النشر:

```bash
curl -o /dev/null -w "%{http_code}\n" https://ndt-insco.github.io/-Project-/edb/index.json
# المتوقع: 200 (حالياً 404)

curl -s https://ndt-insco.github.io/-Project-/edb/index.json | head -c 200
# المتوقع: {"format":"EDB-INDEX","version":"1.0",...

curl -o /dev/null -w "%{http_code} %{content_type} %{size_download}\n" \
  https://ndt-insco.github.io/-Project-/epub/book-vt.epub
# المتوقع: 200 application/epub+zip 29087

curl -o /dev/null -w "%{http_code}\n" https://ndt-insco.github.io/-Project-/epub/index.html
# المتوقع: 200 (صفحة تحميل الكتب)
```

4. افتح `https://ndt-insco.github.io/-Project-/#courses` — يجب أن يفتح تبويب
   المقررات مباشرة. ثم `#practical` و`#paths` و`#edb`.

> ملاحظة: `docs/` مخزّن في Git (3.7 MB للبناء). البديل هو بناء في CI ونشر
> Artifact، لكن ذلك يغيّر إعداد Pages الحالي (`main`/`docs`) ويحتاج صلاحية
> إعدادات المستودع. لم أغيّره حتى تقرر.

## 6. إعادة إنتاج المراجعة

```bash
npm ci
npm run verify        # lint + 112 اختباراً + edb:check + المنشور + الروابط + build + site:check
npm run dev           # معاينة محلية
```

`verify` يجب أن ينتهي بـ `✓ docs/ is deployable` و`0` أخطاء. أي فشل في
`site:check` يعني أن ما سيُنشر لن يعمل، حتى لو نجح البناء.
