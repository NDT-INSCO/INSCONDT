# خطة مراجعة مقررات NDE-Ed — تعيين المراجعين المستوى الثالث

> الحالة: **المراجعة الفنية معلّقة (pending)** — المحتوى منشور للتعلم الذاتي فقط.
> تاريخ الإصدار التحريري: 2026-10-21.
>
> لا تُذكر أسماء مراجعين لم يعيّنهم المالك فعلياً. الجدول أدناه يحدد **الأدوار
> المطلوبة** والملفات التي يوقّع عليها كل دور. عند التعيين يُملأ عمود الاسم
> والتاريخ ويُرفع توقيع المراجعة.

---

## 1. لماذا هذه الخطة؟

مقررات NDE-Ed بُنيت من هيكل موضوعات [nde-ed.org](https://www.nde-ed.org/)
مع صياغة وأمثلة وأسئلة أصلية. الصياغة الأصلية لا تعفي من المراجعة الفنية:
قد يكون رقم أو حد أو تفسير كود قديماً أو ناقصاً. لذلك:

- **لا** يُوصف أي مقرر بأنه «معتمد» أو «مراجع» قبل التوقيع.
- **لا** تُستخدم المقررات كإجراء فحص أو أساس قرار قبول.
- كل مقرر يعرض تاريخ مراجعة تحريرية (`NDE_ED_EDITORIAL_DATE`) وبيان حدود.

> وتظهر في واجهة المقرر نفسها كشارة. الجدول هنا نسخة بشرية؛ لا تعدله وحده.

| --- | --- | --- | --- | --- | --- |

| UT | `src/data/ndeEd/ut.ts` | UT Level III | — | مطلوب | `pending` |
| RT | `src/data/ndeEd/rt.ts` | RT Level III | إشعاع/جرعات | مطلوب | `pending` |
| ET | `src/data/ndeEd/et.ts` | ET Level III | — | مطلوب | `pending` |

**قواعد مفروضة بالكود** (`tests/reviewAndLinks.test.tsx`):

- `pending` لا يحمل مراجعاً ولا تاريخاً ولا بصمة.
- `assigned` يحتاج اسم المراجع وتاريخ التعيين، ولا يحمل بصمة.
- `reviewed` يحتاج الاسم والتاريخ وبصمة SHA-256 من 64 خانة، ومراجع سلامة إن
  كانت الطريقة تتطلب ذلك.
- لا يستطيع أي مقرر أن «يدّعي» مراجعة لم توقّع لأن الاختبار يفشل.

**قاعدة الفصل:** لا يراجع شخص المقرر الذي كتبه. المراجع الفني يجب أن يحمل
شهادة Level III سارية في الطريقة (ASNT أو ISO 9712) أو ما يعادلها، ويوقّع
على النسخة المحددة بالمحتوى (checksum) لا على «النسخة العامة».

## 3. ما يراجعه كل دور

### 3.1 المراجع الفني (Level III)

- [ ] صحة الفيزياء والمعادلات والوحدات (مثال: `δ = 1/√(π f μ σ)`، `N = D²/4λ`).
- [ ] صحة أرقام المعايرة والشدة والزمن (مثال: شدة MT لكل 25 mm، زمن التطوير).
- [ ] عدم تحويل قاعدة تقريبية إلى حد إلزامي دون ذكر الكود والإصدار.
- [ ] صحة تفسير الإشارة وحدود الطريقة (اتجاه الشق، العمق الأقصى، النفاذية).
- [ ] أن كل سؤال معرفة له جواب واحد صحيح بلا لبس، وأن التفسير يشرح «لماذا».
- [ ] أن الأمثلة المحلولة لا تنتهي بقرار قبول/رفض بلا مرجع.

### 3.2 مراجع السلامة

- [ ] RT: الجرعات، الحواجز، المراقبة، الترخيص المحلي.
- [ ] PT: التهوية، معدات الحماية، إدارة النفايات، الحساسية الجلدية.
- [ ] MT: المجالات المغناطيسية، الأجهزة الكهربائية، إزالة التمغنط.
- [ ] ET: الكهرباء، الحرارة، الأسطح الساخنة.
- [ ] لا توجد تعليمات قد تُفهم كإذن بالعمل دون تصريح موقع.

### 3.3 المحرر العربي

- [ ] المصطلح العربي ثابت عبر المقررات (مثال: «عمق الاختراق القياسي» لا «عمق النفاذ»).
- [ ] لا ترجمة آلية غير مراجعة، ولا خلط بين «الفحص» و«الاختبار» بلا ضبط.
- [ ] الأرقام والوحدات بصيغة موحدة، والفاصلة العشرية مفهومة.
- [ ] اتجاه RTL سليم، والمعادلات تُعرض LTR داخل سطر عربي.

## 4. إجراء التوقيع

1. المراجع يفتح الملف ويطابق المحتوى مع المصدر والكود المرخص.
2. يسجل ملاحظاته في Issue أو في سجل المراجعة أدناه.
3. تُصحح الملاحظات، ثم يُعاد بناء EDB (`npm run edb:build`) لأن التصحيح
   يغيّر البصمة.
4. يوقّع المراجع على **بصمة المحتوى** (SHA-256 من `public/edb/index.json`)
   لا على تاريخ فقط.
5. يُحدّث صف المقرر في الجدول: الاسم، رقم الشهادة (اختياري، دون صور)، التاريخ،
   البصمة.

## 5. بعد التوقيع

- يمكن تغيير شارة المقرر من **«مراجعة فنية معلّقة»** إلى **«راجعها Level III»**
  مع إظهار الاسم والدور والتاريخ.
- **لا** تصبح المقررات شهادات حتى بعد المراجعة؛ المراجعة الفنية لا تمنح
  اعتماداً ولا تستبدل اختبار الجهة المانحة.
- أي تعديل لاحق في محتوى المقرر يُبطل التوقيع ويعيد الحالة إلى «معلّق» حتى
  إعادة المراجعة.

## 5.1 مراقبة روابط القراءة

```bash
npm run links:check          # فحص بنيوي بلا شبكة (داخل npm run verify)
npm run links:check:online   # فحص الوصول الفعلي (workflow أسبوعي)
```

يفحص البنية: https فقط، مضيفين مسموحين (`nde-ed.org`, `asnt.org`)، عدم تكرار
المعرّف أو الرابط، عدم وجود روابط بديلة، ولاحقة `.xhtml` المتوقعة.
فحص الوصول يعمل في `.github/workflows/link-monitor.yml` أسبوعياً ولا يعطّل
الدمج عند انقطاع الشبكة (يفصل بين «الشبكة محجوبة» و«الرابط مكسور»).
